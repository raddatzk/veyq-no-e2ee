# ADR 0038 — `ErrorResponse` extracted to `_common`; the rest kept inline behind a hardened drift guard

- Status: Accepted
- Date: 2026-07-12 (extraction + guard-hardening: 2026-07-21)

> Realises audit finding **#76 (P3f)**. Originally kept every shared component inline + a drift guard, because
> external `$ref` then needed a bundler. The revisit trigger (below) fired at F6 (review-2026-07-14): the blocker
> was gone, so **`ErrorResponse` was extracted to `contracts/api/_common.openapi.yaml`** via external `$ref`, and
> the guard was kept — shrunk (no longer checks `ErrorResponse`) and hardened (enum check ≥2→≥1 overlap). The
> rest stays inline by measured cost — see *Decision*.

## Context

`ErrorResponse` is defined in all **9** `contracts/api/*.openapi.yaml` (structurally byte-identical — only the
`code.example` value varies); `bearerAuth` in **8**; the same logical enums repeat across specs
(`NodeKind` [FOLDER, MEMORY, CHAPTER] ×2, derivative-kind [THUMBNAIL, PREVIEW] ×3, credential-method ×3,
membership-role [OWNER, MEMBER] ×2, suite-version [v1] ×3); `ScopeId`/`TenantId` path-params are redeclared.
Today this duplication is a **documented, deliberate** invariant — the specs are independent single documents so
each generator target consumes exactly one self-contained file, and colliding component names across specs are
why they can't share a generator module.

The audit asks to extract a shared `_common.openapi.yaml` and `$ref` it. **Both consumers resolve cross-file
`$ref` natively**, established empirically:

| Consumer | Resolves cross-file `$ref`? | Note |
|---|---|---|
| web (openapi-generator typescript-fetch) | **yes** | swagger-parser resolves relative refs in place |
| backend (openapi-generator 7.21, Quarkus) | **yes** | reads specs in place |

**This decision originally rested on a blocker that no longer exists.** It was taken when a generator that
could not resolve external references at all was a consumer: extraction would have needed a bundler plus a
committed, generated spec in the tree, and *that* cost — not the merit of `$ref` — is what defeated it. With
only web and backend left, extraction needs no bundler, no committed artifact, and no reversal of a toolchain
requirement. The "self-contained spec" invariant is now a **convention we keep, not a constraint we are
under**, and this ADR's conclusion stands on its second argument alone:

The duplication `$ref` would remove is ~50 lines of **stable** boilerplate: the `ErrorResponse` schema is
already byte-identical across all 9 specs (only the per-domain `code.example` varies), `bearerAuth` differs only
in `description`, and the shared enums are duplicated-not-drifted. The actual risk is **future** drift, not present
disorder. That risk is fully addressed by a check — which needs none of the machinery. That argument is real,
but it is a *judgement about size*, not an impossibility — so the honest status is **weaker than it reads**, and
the revisit trigger below is now the live one.

## Decision

**Extract `ErrorResponse` to `contracts/api/_common.openapi.yaml`; keep the rest inline behind a hardened drift
guard.** The revisit trigger below fired (F6, 2026-07-21); the components split by what extraction actually costs
— measured against the generated output, not assumed:

1. **`ErrorResponse` is single-sourced** in `_common.openapi.yaml`, `$ref`'d by all 9 specs — the ×9 byte-identical
   copy with the most to gain. **Mechanism, learned by measuring the generated bytes:** a response that `$ref`s
   the shared schema **directly** makes openapi-generator invent a per-operation model name
   (`GetAccountKeyMaterial401Response`), *losing* the `ErrorResponse` type — not a pure refactor. The fix that
   keeps generation byte-identical is a **local `$ref` alias**: each spec keeps
   `components.schemas.ErrorResponse: {$ref: '_common…'}`, so every response still references the local name.
   Backend output is then byte-identical; web (openapi-generator 7.23) additionally emits one *unreferenced,
   unexported* inline clone per module — harmless dead code in the gitignored generated tree, not worth fighting.
   `_common` is excluded from the backend spec glob (`openapi.gradle.kts` — it is a `$ref` target, not a spec) and
   unlisted in web's `generate:api`.
2. **`bearerAuth` (×8), `ScopeId`/`TenantId`, and the shared enums stay inline** — extraction there is *not* free:
   `bearerAuth`'s five `description`s carry real per-domain authorization nuance, and the enums are mostly *inline*
   properties, so `$ref`-ing them would change the generated type (a nested `Parent.MethodEnum` → a named import)
   and touch both surfaces. Not worth it for stable boilerplate that never drifts.
3. **The guard (`scripts/validate_contracts_common.py`) stays — shrunk + hardened.** It no longer checks
   `ErrorResponse` (single-sourced ⇒ cannot drift). Its enum check is tightened from the old `overlap≥2` heuristic
   — which silently missed a drop on a 2-value family (`[OWNER]` for membership-role, overlap 1) and every
   1-value `suite-version` drift — to **≥1-overlap ⇒ must match exactly**, honoring the declared
   `[DEVICE, DEVICE_KEY]` variant. Residual, principled: a *full rename* (0 shared values) is indistinguishable
   from a new domain enum, so no value-based check can see it.
4. **Collection-wrapping is left alone** — the bare-array / `{results}` / `{items}` / domain-key mix encodes an
   intentional batch-vs-list distinction, so it is a design choice, not drift; the guard does not police it.

## Consequences

- **`ErrorResponse` now has a single-source *file*; the rest has the single-source *guarantee* without one.** The
  ×9 `ErrorResponse` copy is gone — one definition in `_common`, `$ref`'d. The still-inline components
  (`bearerAuth`, path-params, enums) can no longer drift silently either, because the guard is the enforcement a
  bundler's `$ref` would have given, while every generator keeps consuming exactly what it did before.
- **On-disk duplication remains only where extraction costs more than it saves.** A reviewer still sees
  `bearerAuth` in eight files and the enums inline; editing one means editing all copies (the guard fails until
  they agree). Accepted: those change ~never, and — unlike `ErrorResponse` — extracting them is not free
  (bearerAuth's per-domain `description`, the inline enums' generated-type change).
- **Extraction to `_common.openapi.yaml` + external `$ref` — done for `ErrorResponse`, scoped out for the rest.**
  The original proposal was rejected when it needed a bundler + committed specs; that blocker was gone (both
  generators resolve refs in place), so at F6 it was executed for the one component where it is a *pure* refactor.
  The measured reason the rest stayed inline is in *Decision* §2 — not proportion-guessing anymore, but the
  generated-type change for inline enums and bearerAuth's lost nuance. The revisit trigger has fired and is spent
  for `ErrorResponse`; it re-arms for the rest if a generator gains clean external-enum handling or the shared
  surface grows.
