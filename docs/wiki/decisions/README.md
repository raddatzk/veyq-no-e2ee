# Architecture Decisions

> Important, expensive or risky decisions, with rationale. veyq records stable decisions as **ADRs**.
> The **20 legacy ADRs** in `docs/adr/` (reference) remain valid and are migrated here incrementally.

## Decision log

| ID | Decision | Status | Summary |
|---|---|---|---|
| AD-01 | **Documentation: feature-first + arc42 coverage**, published as a GitHub Wiki auto-synced from `docs/wiki/**`. | Accepted | Features/use-cases primary; cross-cutting separate; AI methodology in `docs/ai/`. |
| AD-02 | **Full E2EE everywhere** (all scopes); the server is always blind. | Accepted | The paramount invariant; drives everything. See [Security Model](../crosscutting/security-model.md). |
| AD-03 | **Envelope encryption, per-subtree content keys**; share token in the URL fragment. | Accepted | Least-privilege key access; token never reaches the backend. |
| AD-04 | **Shared vs. unshared** is the central axis for risk and dedup (not the scope folder). | Accepted | A shared personal Memory is treated as "shared". |
| AD-05 | **Trust & Safety at the share boundary**; private content is unscannable. | Accepted | Operator decrypts reported shares only; CSAM partitioned. Legal apparatus before SaaS launch. |
| AD-06 | **Key recovery (no escrow)**: multi-device, Emergency-Kit (Secret Key) + password, and a **standalone high-entropy recovery code** (single-use — redeeming it invalidates it and generates a new one). Only losing all paths = residual loss. | Accepted | Distinct from the Secret Key (AD-08). |
| AD-07 | **Key-directory trust: TOFU/pinning now, Key Transparency later (core).** | Accepted (phased) | Mitigates active key-substitution. |
| AD-08 | **Adopt a Secret Key (2SKD)** — a high-entropy *second factor* combined with the password (breach-resistance). **Not** a recovery mechanism (that is AD-06). | Accepted | Independent of Key Transparency. |
| AD-09 | **Dedup: source-dedup (unshared) / convergent-encryption + per-scope secret (shared).** | Accepted | Confirmation-of-file weakness is moot in shared scopes. |
| AD-10 | **Deletion & Erasure**: soft-delete + retention + hard-purge + backup rotation; deletion privilege; blob-level purge; audit. | Accepted | Supersedes legacy flat permissions (ADR 0005); own-account = ADR 0017. |
| AD-11 | **Agent Mode** is the only processing path (server never a worker); edge compute. | Accepted | See [Agent Mode](../crosscutting/agent-mode.md). |
| AD-12 | **Agent-Mode liveness & job assignment**: **tiered** — light derivatives synchronous on the uploader (always shown); heavy derivatives eventual via queue, synchronous fallback only on a capable uploader, else **pending** (original viewable); no capable **participant** worker → derivative simply not produced (accepted). Jobs assigned by **participation** (`responsibility ⊆ access`); the blind server schedules on reported client **status** (power/Wi-Fi/idle) + **capabilities**. | Accepted | See [Agent Mode](../crosscutting/agent-mode.md). |
| AD-13 | **Search**: client-side bounded-text index; low-sensitivity operational metadata server-visible. | Accepted | Semantic/visual search deferred. |
| AD-14 | **ML on-device only; server-side ML/semantic search out of scope for v1** (v1 = structural + keyword; faces / semantic / embeddings / NL / RAG deferred — on-device & encrypted). | Accepted | Server-ML breaks E2E **and** self-hostability. |
| AD-15 | **Modular monolith first**; extract a service only when a quality scenario forces it. | Accepted | Two deployments (Compose + Helm). See [Deployment](../overview/deployment.md). |
| AD-16 | **API is internal** (no third-party API product); OpenAPI generates clients, rendered via Redoc. | Accepted | Smaller surface; no public stability guarantees. |
| AD-17 | **Journal live collaboration via Yjs (CRDT) over WebSockets**, with the CRDT client-side. | Accepted | See [Live Collaboration](../crosscutting/live-collaboration.md). |
| AD-18 | **Journal persistence**: encrypted **update-log** for durability + **snapshot compaction**, snapshots chosen **round-robin by connect time gated by ≥ `Y` updates**, monotonic-by-offset, atomic swap. | Accepted (params open) | See [Live Collaboration → Persistence](../crosscutting/live-collaboration.md). |
| AD-19 | **Collaboration transport & storage**: a thin **blind relay folded into the Quarkus backend** (no Node sidecar; replaces Hocuspocus), Yjs CRDT client-side; **op-log in MariaDB (batched segments)**, **snapshots in the encrypted blob store**; in-memory broadcast + async/relaxed-durability persist; **Redis Streams + pub/sub** as the deferred SaaS scaling step. | Accepted (scale-path deferred) | See [Live Collaboration → Transport & storage](../crosscutting/live-collaboration.md). |
| AD-20 | **Native collaborative editor uses `yrs` (the Yjs-compatible Rust CRDT) directly — no WebView stopgap.** Web uses CodeMirror + Yjs; relay/wire-format are client-agnostic → full interop. | Accepted | See [Live Collaboration → Clients](../crosscutting/live-collaboration.md). |
| AD-22 | **Bounded-context cut** (modular monolith): Core (Memory incl. enrichment subdomains / Media / Journal / Sharing / **People**), Access (Identity & Auth / Spaces & Membership / **Key Management**), Generic (Processing / Trust & Safety / Operations / Notifications). **Authorization owned by Spaces & Membership**, consumed everywhere; **People** is its own privacy-bounded context; tracks/playlists/weather/maps are Memory subdomains. | Accepted | See [Architecture → Bounded contexts](../overview/architecture.md). |
| AD-21 | **Key provisioning / onboarding**: new members bootstrap via a **single-use temp-wrap token** (email invite *and* self-serve link are the same mechanism; token in URL fragment → operator-blind; re-wrap to own key on register, temp deleted; TTL, revocable). A **shared public link** (X slots) is a riskier convenience requiring **explicit owner risk-confirmation + TTL + rotate-on-close** (limits spam, not confidentiality). The **grant path** (no key in channel; owner/user-side agent wraps on approval) is the private alternative, automation deferred. Registration ≠ share. | Accepted (grant-automation deferred) | See [Security Model → Key provisioning](../crosscutting/security-model.md). |
| AD-23 | **Capability versioning & compatibility**: capabilities are a SemVer'd **manifest** — adding = **minor**, removing/changing = **major**. Removal is **announced ~4 months ahead** (`sunsetAt`; capability stays advertised + working). Clients **auto-update silently first**, then **actively warn the user only in the last ~2 months** before the sunset; then removed at the sunset. Clients keep a removed capability **~12 months** then drop it (CI gates from the manifest); discovery detects skew on connect ("server too old" / "update the app"); **self-host SLA ≈ keep the server within ~12 months of current**. | Accepted | See [Platform Concepts → Versioning & compatibility](../crosscutting/platform-concepts.md). |
| AD-24 | **Two-layer revocation** (shares & members): **instant server-side token/access invalidation** (no keys, effective with no client online) + **eventual content-key rotation** by a key-holder (defense-in-depth, queueable). Already-downloaded-and-decrypted content cannot be retracted. | Accepted | See [Security Model → Revocation](../crosscutting/security-model.md). |
| AD-28 | **Segmented content encryption for streaming**: video transcodes are written as **HLS/DASH-style segments, each encrypted independently** (AES-256-GCM, nonce from the segment index); the client fetches ciphertext ranges and decrypts per segment into the player (MSE / native resource loader), so **seek and adaptive bitrate** work while the **server stays blind**. **No browser EME/DRM** (needs a license server / breaks self-hosting). Originals stay single blobs (download-only); only the streamable rendition is segmented. | Accepted | See [Security Model → Streaming](../crosscutting/security-model.md), [Agent Mode](../crosscutting/agent-mode.md). |
| AD-27 | **External rendering calls** (map tiles, reverse geocoding, later weather): the blind server cannot render maps, so the **client** calls a third party — which reveals the viewed **coordinates** to that provider. Mitigation: **explicit consent**, a **public provider in v1**, and a **self-hostable endpoint later** for zero third-party leak; **never proxy through our server** (that would expose the operator). Results (e.g. place names) are stored encrypted. | Accepted | See [add-map-tracks](../features/memory/use-cases/uc.memory.add-map-tracks.md). |
| AD-26 | **Blinded slug tokens for E2E permalinks**: names are encrypted but nodes are addressed by human-readable permalinks → per-parent slug uniqueness is enforced via a blinded token `HMAC(scopeKey, parentId ‖ slugify(name))` with a server `UNIQUE(parentId, slugToken)` constraint. Race-free, server-blind, zero operator leak; outbound links use `Referrer-Policy: no-referrer`. | Accepted | See [Security Model → Names, slugs & permalinks](../crosscutting/security-model.md). |
| AD-25 | **Crypto primitives & post-quantum**: content = **AES-256**; key wraps = **HPKE-style N-recipient with a hybrid KEM (X25519 + ML-KEM-768) from v1** (harvest-now-decrypt-later on decades-long memories); password→key = **Argon2id** over password + Secret Key; signatures Ed25519 → **ML-DSA** (hybrid) later. **Crypto-agility mandatory** — versioned suite id negotiated via capability discovery; no home-grown crypto. | Accepted | See [Security Model → Crypto primitives](../crosscutting/security-model.md). |
